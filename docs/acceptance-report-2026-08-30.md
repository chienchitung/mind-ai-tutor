## 需修正的問題

### 1. 優先：既有 AI 出題 API 缺少登入檢查

- 證據：`app/api/gemini/quiz/route.ts:4` 直接解析內容並呼叫生成服務；`middleware.ts:100` 的套用路徑也不包括這個 API。
- 隔離模擬測試：不提供登入 Cookie，生成服務仍被呼叫一次，回傳 200。生成服務使用替身，沒有實際呼叫 AI 或寫入資料。
- 影響：部署環境若有有效 Gemini 金鑰，未登入者也可能消耗出題服務。
- 注意：這是既有出題端點的問題，與本次已保護的 `/api/quizzes` 儲存端點不同。
- 建議：伺服器端先驗證使用者，再加入請求大小、題數及頻率限制。

### 2. 優先：輸入 `/` 會搶走表單焦點

- 重現：建立課程 → 點選 Genially/Canvas 連結欄 → 輸入 `/`。
- 實際結果：開啟「指令選單」，斜線未正常輸入欄位。
- 位置：`app/components/global/CommandMenu.tsx:47`。
- 建議：一般 `/` 快捷鍵應略過 input、textarea、contenteditable 及中文組字中的輸入；保留明確的快捷鍵組合。

### 3. 離開保護仍有缺口

- `hooks/useUnsavedChanges.ts:19` 只監聽連結、程式導頁事件與 `beforeunload`，沒有處理同頁應用程式的上一頁／下一頁導覽。隔離測試送出 `popstate` 時提醒次數為 0；尚未完成各瀏覽器端到端重現。
- `app/ai-quiz/page.tsx:1839` 只在沒有開啟測驗時檢查整個清單的未儲存草稿；開啟一份已儲存測驗時，另一份未儲存草稿可能沒有被離開提醒涵蓋。子元件在第 328 行只檢查當前測驗。此項為程式檢查發現，尚待真實多份草稿操作驗證。
- 建議：統一計算頁面整體的未儲存狀態，並以草稿保留／復原搭配導覽提醒；不能只宣稱所有離開方式都有保護。

### 4. 設定頁頂端標題錯誤

- 實測桌機及窄螢幕的設定頁：主要標題是「設定」，頂端導覽卻顯示「儀表板」。
- 位置：`app/components/layout/AppTopbar.tsx:19` 的路徑對照漏掉 `/settings`，因此套用儀表板預設值。
- 建議：補上設定、個人資料等路徑標題。

### 5. 新課程摘要的空白提示未中文化

- 重現：建立課程，不填任何欄位便送出。
- 實際結果：「學習路線圖摘要」下方顯示英文 `Required`，其他主要必填提示是中文。
- 原因：`app/lessons/page.tsx:555` 的新增表單重設缺少 `cardDescription`，使 Zod 收到 undefined 而不是空字串。
- 建議：新增重設也給予空字串預設值，並統一 required／invalid type 的中文提示。
