# 遊戲封面與原始品牌還原

## 使用方式

- 原始魔法棒與 MindAiTutor 字樣的 17 段 SVG 路徑取回自 `9dbc292`，只調整畫布留白與側邊欄排版，不替換字型或描繪圖形。
- 數位遊戲 → 建立／編輯 →「上傳封面圖片」。
- 建議 **1280 × 720 px（16:9）**；接受 JPG、PNG、WebP，原檔上限 **5 MB / 2,400 萬像素**。
- 預設置中裁切，可調整縮放、水平與垂直位置。含重要文字的圖片可選「完整保留圖片（白色留邊）」。
- 預覽與輸出使用相同座標，瀏覽器輸出 1280 × 720 JPEG（品質 0.88）；透明區域合成白色。
- 按「使用此封面」只建立本機草稿；按「更新／創建遊戲」才上傳。裁切尚未確認時，遊戲儲存按鈕暫停使用。
- 取消裁切會保留先前封面，尚未儲存的新封面也可放棄。網址輸入仍保留在「或使用圖片網址」中。
- 不會自動改動現有遊戲的封面、名稱、關卡或遊戲引擎。新封面仍寫入 `digital_games.thumbnail_url`。

## Supabase 上線前設定

已於 2026-08-30 在 MindAiTutor 專案執行 `scripts/add_game_cover_storage.sql`。其他環境請在目標專案 SQL Editor 執行一次：

- 建立 `game-covers` **公開封面圖片儲存桶**，不是新的業務資料表。
- 伺服器限制每個物件最多 5 MB，只接受 JPEG。前端先解碼原圖，再重新編碼成 JPEG。
- INSERT、SELECT、DELETE 僅授權登入者自己的 `<auth.uid()>/<隨機 UUID>.jpg` 路徑。
- 無匿名上傳、無物件覆寫權限；公開網址供遊戲頁和列表使用，不開放匿名列舉。
- 使用既有 Supabase 公開設定和登入工作階段，不需要 service-role key 或新環境變數。

封面是公開素材，不適合個資或私密檔案。Supabase 的儲存、流量配額仍適用；不需要金流串接。

## 失敗處理與檔案保留

- 上傳失敗：不寫入遊戲資料，保留本機草稿供重試；儲存桶未建立時顯示對應設定提示。
- 遊戲資料確定被資料庫拒絕：嘗試移除**本次新上傳**的物件，不碰原封面。
- 網路中斷造成儲存結果不明：保留新物件，避免刪掉可能已被成功儲存的封面。這類情況可能留下未引用物件，需要管理員日後檢查。
- 更換或移除封面不刪舊物件，以免其他遊戲也使用相同網址；舊圖片清理與用量監控不在本次功能中。

## 驗證

- `npx tsc --noEmit`
- `npx eslint app lib hooks utils components --max-warnings=0`（現有 `npm run lint` 的 `next lint` 與 flat config 不相容，此次直接使用 ESLint，未擴大修改工具鏈。）
- `npm test`：包含原 SVG 雜湊、檔案格式／大小、裁切座標、白色留邊、輸出參數、儲存失敗／回收物件等測試。
- 本機瀏覽器用暫時測試頁驗證實際選檔事件、裁切、鍵盤調整、白邊保留、1280 × 720 JPEG 編碼、取消及錯誤訊息；測試頁交付前移除。
- Supabase 實際驗證：公開桶、5 MB 限制、僅 JPEG、RLS 已啟用、三條擁有者政策皆確認。既有 Storage 政策原本為空，沒有覆蓋其他用途的設定。
- 透過登入工作階段上傳單一測試圖片成功；無登入資訊的 HTTP GET 回傳 200，實際檔案為 1280 × 720 JPEG。測試完成後只移除此測試物件，沒有寫入正式遊戲資料。
- 完整遊戲資料新增／更新與重新載入並未對正式資料執行測試；儲存回呼成功／拒絕／網路失敗由自動測試覆蓋。

儲存權限與 SDK 依據：[Supabase Storage 存取控制](https://supabase.com/docs/guides/storage/security/access-control)、[Standard Uploads](https://supabase.com/docs/guides/storage/uploads/standard-uploads)。
