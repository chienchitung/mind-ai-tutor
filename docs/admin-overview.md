# 系統管理頁面用途與載入修正

## 目前用途

`/admin` 是管理員的**唯讀總覽**，不是完整帳號管理或系統設定工具：

- 查看學生、行事曆事件、課程、回饋的可讀取筆數。
- 查看 `profiles` 中可讀取的姓名、加入日期與角色，搜尋已載入清單。
- 資料仍受目前登入帳號與既有 RLS 限制，統計不保證是全站總數。
- 不修改角色、不停用帳號、不新增使用者，也不處理金流。

## 為什麼會一直看不到內容

原管理頁 `useEffect` 依賴 `t`，但 `useTranslation()` 每次呼叫都建立新的 `t` 函式。載入設定 state 後重繪，又觸發資料請求；完成後更新 state 再次重跑，因此畫面持續切回載入狀態。瀏覽器記錄亦觀察到大量重複的管理資料讀取錯誤。

此外，原實作把使用者清單失敗當成整頁失敗，卻沒有處理各統計查詢的錯誤，容易把「讀取失敗」誤認成「沒有資料」。

## 本次修正

- 每種語言使用穩定的翻譯函式；切換語言仍即時更新文字。
- 管理資料只在進入頁面／手動重新整理時載入；輸入搜尋或重繪不重抓資料。
- 每次查詢提供取消機制與 15 秒上限，離開頁面取消舊請求。
- 各統計／使用者清單的錯誤獨立處理；失敗顯示提示，不冒充 0 筆。
- 標題、頁面用途及資料權限範圍始終顯示，並提供手動重新整理。
- 區分「沒有使用者」與「搜尋沒有結果」，後者可清除搜尋。
- 保留現有 admin 權限判斷；未放寬任何資料表政策或使用 service-role key。

## 驗證與限制（2026-08-30）

- 自動測試涵蓋翻譯函式參照穩定、正常／部分失敗／逾時、0 筆與失敗的區別，以及匿名、teacher、admin 與角色查詢失敗的權限檢查。
- 本機瀏覽器讀到過學生 1、課程 7、行事曆 0、回饋 0；也驗證了部分查詢失敗時其餘卡片繼續顯示，以及逾時可重試。
- 驗收期間 Supabase SQL Editor 的只讀政策查詢兩次回報 `Connection terminated due to connection timeout`。Auth health HTTP 200，不代表資料庫連線正常。因資料庫連線不穩，使用者清單的成功載入、搜尋與完整資料驗收尚未完成。
- 沒有變更正式資料、使用者角色、RLS 或重啟資料庫。本次程式尚未提交／推送部署。
